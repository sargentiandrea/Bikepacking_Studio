ANALISI PROFONDA v4 — ISTRUZIONI

La continuità automatica dei tre settori è descritta in CONTINUITA.md.
Gli hook usano: node scripts/continuita-hook.cjs sync
Il motore aggiorna anche registro attività, storia e inventari remoti.
I comandi Python sotto restano validi per la sola fotografia locale.
I tre report di continuità sono generati dal motore comune, non mantenuti a mano.

Richiede Python 3.10 o successivo, senza dipendenze aggiuntive.
Dal terminale nella cartella del progetto:

  python analisi_profonda.py

Aggiorna dieci file correnti nella cartella REPORT, senza creare nuove
copie datate. Il progetto predefinito è la cartella dello script.

Per una verifica senza scrivere alcun report:

  python analisi_profonda.py --check

Per escludere la lettura SQLite aggiungi --no-db.
Per analizzare un'altra cartella aggiungi --root "C:\percorso\progetto".
Se python non è disponibile, usa il percorso di un interprete funzionante.
Un eventuale lanciatore esterno .bat deve usare un interprete valido;
lo script non installa Python e non ripara l'ambiente virtuale dell'app.

COME LEGGERE I RISULTATI

1. AI_BRIEF.md: punto di ingresso, fotografia sintetica e limiti.
2. report.md: moduli, dipendenze, rotte, prove, errori e confronto.
3. DB_SCHEMA.md: schema, indici, chiavi esterne e conteggi SQLite reali.
4. CONFIG_FILES.md: struttura delle configurazioni, senza copiarne i valori.
5. EXTERNAL_SERVICES.md: URL osservate nel Python, senza contattare servizi.
6. STATO_ATTUALE.md: stato ricavato dalla stessa scansione verificabile.
7. PERCORSO.md: ultimi 80 commit locali raggiungibili da HEAD.
8. riepilogo.txt: riepilogo minimo.
9. analisi.json: dataset completo, con file e righe delle prove.
10. ULTIMO_RUN.json: piccolo manifest con impronte per il prossimo confronto.

I report condividono un identificativo di scansione. Il manifest viene
scritto per ultimo; la scansione successiva segnala report mancanti o
modificati. Alla prima esecuzione v4 la vecchia baseline è incompatibile:
il confronto sarà disponibile dalla scansione successiva.

INTERPRETARE CORRETTAMENTE LA FOTOGRAFIA

Funzioni di modulo, metodi e funzioni annidate hanno conteggi separati.
Le rotte distinguono i metodi HTTP anche quando il percorso è uguale.
Le tabelle SQLite lette sono separate dalle tabelle candidate nelle query.
Un simbolo senza riferimenti statici è un indizio da verificare, non una
prova che sia inutile. La dimensione di un modulo non è un voto di rischio.
Errori di lettura, sintassi o JSON sono riportati; l'uscita vale 1 in caso
di errori della scansione o della lettura del database.

Il database è aperto in sola lettura immutable, senza file laterali.
Se esiste un WAL non vuoto, la lettura viene saltata e il limite dichiarato.
Per una fotografia SQLite affidabile, esegui l'analisi con l'app chiusa.
Nessun modulo dell'app viene importato o eseguito. Non vengono svolti test
funzionali né verifiche di server, R2 o servizi remoti.
HTML, JavaScript e CSS sono inventariati, non collaudati.
Le cartelle escluse sono elencate nei report e nella costante EXCLUDED.

MEMORIA DEL PROGETTO

STORIA_PROGETTO.md conserva la memoria ricostruita dalle chat: non viene
riscritta. Principi, regole, visioni e piani rimangono documenti separati.
I titoli Git e i piani non dimostrano il completamento delle funzionalità.
REPORT/ARCHIVIO è escluso. Nessun commit, push o cancellazione automatica.
Non usare un indizio statico come autorizzazione a cancellare codice.
